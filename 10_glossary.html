Словарь терминов

Термины из восемнадцати докладов — простыми словами. В справочнике 97 понятий.

Материалы и официальные записи по всем терминам →

Agent / ИИ-агент
Система, в которой модель не только отвечает, но и выбирает и выполняет действия через инструменты.
LLM
Большая языковая модель, которая обрабатывает последовательности токенов и генерирует продолжение.
Harness
Слой исполнения вокруг модели: работа с инструментами, контекстом, задачами, файлами и ограничениями.
CLI
Command-line interface — интерфейс командной строки для запуска и управления программами.
IDE
Среда разработки с редактором, отладкой и инструментами работы с проектом.
Tool calling
Механизм, с помощью которого модель выбирает и вызывает заранее объявленные операции.
MCP
Model Context Protocol — протокол взаимодействия ИИ-приложения с внешними инструментами и ресурсами.
Skill
Повторяемая процедура для агента: инструкции, примеры, правила и иногда вспомогательные файлы.
AGENTS.md
Файл инструкций, задающий устойчивые правила работы агента внутри проекта.
System prompt
Инструкции высокого приоритета, задающие общие рамки поведения системы.
Context / Контекст
Информация, доступная модели в текущем запросе: правила, история, файлы и результаты инструментов.
Context window
Максимальный объём входных и создаваемых токенов, учитываемых в рамках одной операции модели.
Context engineering
Управление тем, какую информацию, когда и в каком виде передают модели.
Compaction
Сжатие ранее накопленного контекста для продолжения долгой работы.
Dictation
Голосовая постановка задач через распознавание речи.
VPS
Virtual Private Server — виртуальный сервер для постоянно работающих сервисов.
Webhook
Событийный вызов внешней системы, запускающий действие по HTTP.
Sandbox
Изолированная среда выполнения, ограничивающая последствия ошибок или недоверенного кода.
AI-native
Проектирование процессов и организации с учётом того, что значительную часть операций выполняют агенты.
AI-first
Подход, при котором возможности ИИ учитывают с самого начала проектирования процесса или продукта.
Data core
Согласованное ядро данных организации: сущности, связи, версии, права и происхождение информации.
Source of truth
Канонический источник, в котором определён достоверный статус конкретных данных.
Audit log
Журнал, позволяющий восстановить, кто, когда, зачем и каким способом изменил систему.
Trace
Связанный набор событий одного выполнения, включая действия и вызовы инструментов.
Idempotency
Свойство операции, при котором её повторное выполнение не создаёт дополнительных нежелательных эффектов.
RBAC
Role-Based Access Control — управление правами доступа на основе ролей.
Least privilege
Принцип минимальных полномочий: выдавать только права, необходимые для конкретной задачи.
Rollback
Отмена изменений или возврат системы к корректной версии.
Eval
Набор сценариев и правил измерения качества модели или агентного процесса.
Golden set
Небольшой эталонный набор кейсов с известным ожидаемым результатом.
Regression
Регрессия — ухудшение прежде работавшего поведения после изменения.
Orchestration
Координация нескольких исполнителей, ресурсов, этапов и проверок для общей задачи.
Coordinator
Компонент или агент, который распределяет работу, контролирует статусы и собирает результат.
Subagent
Агент, которому другой агент делегирует ограниченную подзадачу.
Long-horizon task
Длительная многоэтапная задача, в которой существенны сохранение цели, контроль и передача состояния.
Worktree
Отдельная рабочая директория Git, связанная с репозиторием и выбранной веткой.
Reward hacking
Ситуация, когда система улучшает показатель оценки, не достигая настоящей цели.
Invariant
Свойство системы, которое должно оставаться истинным после любых допустимых изменений.
SDD
Spec-Driven Development — процесс разработки, направляемый явной спецификацией поведения и ограничений.
Brownfield
Существующий проект с унаследованным кодом, контрактами и историей архитектурных решений.
Greenfield
Новый проект, который создаётся без необходимости поддерживать существующий продукт.
PRD
Product Requirements Document — документ, фиксирующий потребности, требования и цель продукта.
ADR
Architecture Decision Record — запись о важном архитектурном решении и его обосновании.
BDD
Behavior-Driven Development — разработка, ориентированная на проверяемые сценарии поведения.
Gherkin
Формат описания сценариев в виде «Дано / Когда / Тогда».
TDD
Test-Driven Development — цикл написания теста, реализации и рефакторинга.
Quality gate
Контрольная проверка, без прохождения которой следующая стадия не начинается.
Feedback loop
Цикл действий, оценки результата и корректировки на основе обратной связи.
Static analysis
Анализ кода без обычного запуска для выявления определённых типов ошибок.
Linter
Инструмент для проверки согласованных правил кода, стиля и иногда ошибок.
Unit test
Тест поведения небольшой изолированной части программы.
Integration test
Тест взаимодействия нескольких компонентов или внешних систем.
E2E
End-to-End — проверка полного пользовательского сценария от входа до результата.
Mutation testing
Проверка силы тестов путём внесения искусственных изменений в код.
Fuzzing
Испытание системы необычными или случайными входными данными для обнаружения дефектов.
Pull request
Предложение включить набор изменений в общую кодовую базу с проверкой и обсуждением.
CI/CD
Практики непрерывной проверки, сборки и доставки изменений.
Inference
Исполнение нейросетевой модели для получения ответа на входной запрос.
Prefill
Этап обработки входных токенов перед генерацией ответа.
Decode
Этап последовательного получения выходных токенов модели.
KV-cache
Кэш промежуточных состояний механизма внимания, используемый для ускорения работы с контекстом.
Prefix caching
Повторное использование ранее обработанного начала входной последовательности.
Cache hit / miss
Попадание в кэш / отсутствие нужного ранее сохранённого состояния.
TTFT
Time to First Token — время до появления первого токена ответа.
P50 / P95 / P99
Процентили: значение, не превышаемое соответственно в 50%, 95% или 99% наблюдений.
RPS
Requests Per Second — количество запросов в секунду.
Throughput
Пропускная способность системы: объём успешно обработанной работы за единицу времени.
VRAM
Память графического ускорителя, используемая для весов, кэша и промежуточных вычислений.
Quantization
Уменьшение точности представления весов или вычислений модели ради экономии ресурсов.
Tool-call accuracy
Доля корректных выборов инструментов и аргументов в заданных сценариях.
Latency
Задержка между поступлением запроса и ответом системы.
SLA
Service Level Agreement — согласованный уровень качества и доступности сервиса.
DORA metrics
Набор метрик потока поставки программного обеспечения и устойчивости изменений.
Lead time
Промежуток от появления задачи или начала изменения до принятого результата.
Developer experience
Опыт разработчика: удобство, трение и субъективные условия работы с инструментами.
ROI
Return on Investment — соотношение результата инвестиций и затрат на них.
Outcome
Изменение поведения, состояния или пользы для пользователя вследствие выполненной работы.
Output
Созданный артефакт или поставленная функция без обязательного подтверждения полезного эффекта.
Countermetric
Ограничивающий показатель, который помогает не улучшать одну метрику ценой ухудшения других.
Discovery
Поиск и проверка того, какие проблемы и решения действительно ценны для пользователя.
Delivery
Реализация и поставка выбранного решения пользователю.
Cognitive load
Когнитивная нагрузка — объём умственных усилий на понимание, решения и удержание контекста.
FOMO
Fear of Missing Out — страх упустить новую возможность, инструмент или важную информацию.
Flow
Состояние глубокой вовлечённости в относительно непрерывную деятельность.
Human-in-the-loop
Процесс, в котором человек подтверждает или проверяет определённые решения системы.
Ownership
Ответственность за результат: принятие решений, сопровождение и устранение проблем.
Evidence-based SDLC
Разработка, в которой решения опираются на воспроизводимые эксперименты и наблюдения, а не на одни предположения.
Spike
Короткий исследовательский прототип, снимающий конкретную техническую неопределённость.
Memory poisoning
Незаметная запись вредоносной инструкции в память агента через недоверенные данные.
Agent-facing API
Интерфейс продукта, рассчитанный на вызовы агента: операции, права, понятные ошибки и состояния.
Provenance
Прослеживаемое происхождение знания: исходный документ, фрагмент, автор, время и путь получения.
Stale knowledge
Вывод, чьи исходные основания изменились и требуют повторной проверки.
Code graph
Граф связей между файлами, классами, функциями и вызовами, полезный для анализа последствий изменения.
Product engineer
Инженер, который соединяет разработку с пониманием проблемы, пользователей и ценности продукта.
Instrumental convergence
Гипотеза, что разные цели могут мотивировать похожие промежуточные действия вроде поиска ресурсов или сохранения доступа.
Human approval gate
Требование подтверждения человеком перед высокорисковой операцией агента.
Golden image
Эталонный образ изолированной среды для воспроизводимого запуска агента.
